## Scope and standard

The release documentation standard is `docs/ddoc-style.md`.
The source Ddoc attached to declarations is authoritative; generated DDox is a
derived publication artifact. Review must distinguish the supported root
import (`import raster;`) from package-private constructors and execution code.

A complete review requires reading **every** supported public declaration and
nontrivial internal function, checking the actual rendered public-only DDox site,
and recording human judgments on semantics and explanations. CI success alone
does not establish that standard.

## Ownership and trusted-boundary review: targeted pass

Reviewed the source bodies and Ddoc around retained ownership and sample access
at the `release/0.2` base commit `580cd06ca0fc489e746deae45c2cebeecfbbad57`.

| Boundary | Source observation | Remaining evidence |
| --- | --- | --- |
| `RasterBackingOwner.retain/release` | Reference count is non-atomic, checked against overflow, and decremented on release; the last owner removes the GC scan range, destroys backing, then frees the control block. | Recheck copying/assignment/reentrancy and thread-sharing assumptions against external compiler probes and runtime tests. |
| `RasterLease.view/tryWritableView` | Default/inert lease returns inert views; writable borrow requires mutable lease and completed validation/certification; borrow is lifetime-bound to the lease. | Confirm DIP1000 and ordinary-mode negative escape probes cover all return and receiver forms. |
| `RasterView.trySample` | Returns a value copy, checks band/region bounds, and relies on constructor validation for signed-stride address arithmetic and reachability. | Review each trusted read/ROI/execution adapter and signed-stride regression matrix. |
| `WritableRasterView.trySetSample` | Uses a narrow trusted `const(void)*` to `T*` conversion after writable certification; checks band and coordinates before writing. | Validate that all factories certify access and no uncertified path constructs a writable view. |
| `validation.checkedCoordinateStride` | Guards positive and negative stride multiplication, including the `ptrdiff_t.min` magnitude. | Check extreme-value tests for both coordinate axes and summed offsets. |
| `validation.validResourceRange` | Rejects non-null-length/null-base metadata and integer address-range wraparound. | Check all callers validate resources before forming `resourceEnd`; integer range checks alone do not prove actual mapped storage. |

This targeted review produced three explanatory Ddoc changes:
- `RasterLease` now explicitly documents non-atomic retained ownership and the
  fact that writable borrows are neither exclusive nor independently retained.
- `RasterView.trySample` no longer speaks about a future adapter; it describes
  the present package-internal execution distinction.
- `validResourceRange` explicitly distinguishes address-range
  representability from ownership or mapping.

**Important:** This is not a proof of memory safety or a complete
function-by-function audit of all `@trusted` boundaries. No source semantics,
attributes, signatures, or tests were changed.

## Writable construction and negative-evidence checklist

A targeted source trace on the post-PR #207 release baseline
(`cca63a9b2821cd26a98792d322207c8f07bd734f`) establishes the
following **control-flow facts**, not a blanket safety certification:

1. `tryMakeWritableRasterView!T` in `writable_view.d` is
   `package(raster)`, accepts return-scoped resource/descriptor slices,
   and calls `validateRasterBackingLayout!T` first. Its
   `certification` out parameter is initialized to an unsuccessful
   state before returning from a failed ordinary validation.
2. On ordinary-validation success, it calls
   `certifyWritableRasterBacking!T`; failed writable coverage produces
   `WritableRasterView!T.init`. Only after both checks succeed does it
   invoke the private `makeWritableRasterViewAssumeCertified!T`.
3. `certifyWritableRasterBacking!T` requires its input metadata to have
   passed ordinary validation. An empty region succeeds without checking
   sample coverage because no samples are reachable; non-empty regions
   check writable coverage for every descriptor.
4. `trySetSample` checks band and relative coordinates before forming
   its address and converting the access-neutral descriptor base to
   `T*`. Its safety therefore depends on correctly certified
   construction, not on bounds checks alone.
5. `RasterBackingOwner` uses a non-atomic reference count. The
   reference-count limit is checked before increment; final release
   removes the conservative GC range before destroying backing and
   freeing the control block.

### Evidence still required before safety sign-off

- Find and inspect the actual **external** negative compilation probes
  for escaping read-only and writable views, mutable access through
  const leases, unsafe direct factories, and mismatched scoped borrows.
  Confirm both ordinary and explicit DIP1000 modes on the documented
  DMD/LDC compiler matrix; do not infer individual probe coverage from
  an aggregate green API gate.
- Record positive ownership tests for lease copy/assignment/destruction,
  moved-from/inert lease behavior, exact-once callback release,
  import failure disposition, and the non-atomic concurrency constraint.
- Confirm all production paths to the private assume-certified factory
  and the package factory, including child-ROI subset reasoning; test-only
  uses of the private factory must not be mistaken for public construction.
- Verify validator tests across negative strides, `ptrdiff_t.min`,
  combined-offset overflow, resource-range wraparound, alignment,
  empty-region and nonempty-region writable-coverage paths.
- Review every remaining `@trusted` boundary individually and compare
  its stated proof preconditions with all call sites.

**Status:** traced source ordering only. The full Ddoc/safety and DDox
publication release-gate checkboxes remain open.

### Compiler-mode distinction

**Do not describe all negative lifetime probes as dual-mode.**

- `release-api-audit.sh` runs **twice** per compiler, without DIP1000
  and with `RASTER_API_AUDIT_DIP1000=1`. That script contains negative
  source-visibility, invalid-sample, copy, and constructor probes.
- `raster_lifetime.sh` and `raster_writable_view_lifetime.sh`
  explicitly pass `-preview=dip1000` to their compile invocations.
  They run **only in explicit DIP1000 mode** in the current workflow.
- Package tests, external positive API contract tests, and
  retained-import link tests run in both ordinary and explicit DIP1000
  modes for the baseline DMD and LDC versions.

Thus the tested combination is **two compilers × explicit DIP1000 for
negative lifetime probes**, not both source modes for those negative
probes. Ordinary-mode negative lifetime rejection is **not yet
qualified**. This is an evidence-coverage gap, not a demonstrated
runtime safety defect.

### Next qualification action

Determine whether these lifetime contracts must reject the same
escapes without DIP1000, and if so introduce separately classified
ordinary-mode compile probes; do not simply delete the flag and turn
compiler-version differences into accidental CI failures. Confirm
expected behavior on the baseline compiler pair before extending the
release matrix. Retain existing DIP1000 evidence and never weaken
expected rejection to make the gate green.

Runtime ownership, all trusted proof obligations, and stride
edge-case coverage remain separate open review items.
