**Status:** In progress; partial source inventory, not a completed release gate.  
**Branch baseline:** `release/0.2` at `1465ee41ebc23d7f5538d5e2d0a8b313a64f7411`  
**Frozen public API:** `freeze/api-0.2.0` at `1ea67cb6ffb2c887f78d160249a293ad74ba5cda`

## Scope and standard

The release documentation standard is `docs/ddoc-style.md`.
The source Ddoc attached to declarations is authoritative; generated DDox is a
derived publication artifact. Review must distinguish the supported root
import (`import raster;`) from package-private constructors and execution code.

A complete review requires reading **every** supported public declaration and
nontrivial internal function, checking the actual rendered public-only DDox site,
and recording human judgments on semantics and explanations. CI success alone
does not establish that standard.

## Identified and corrected

- `writable_view.d` described its public view as available “from E5.4g.1
  onward.” This was development-history vocabulary rather than useful consumer
  documentation. The module now states the current public/API versus
  package-internal boundary without changing code or declarations.

## Second source pass

The following six modules were inspected at module-documentation level and
for the presence of trusted boundaries. This remains a partial audit, not
line-by-line validation of all declarations.

| Module | Initial observation | Follow-up |
| --- | --- | --- |
| `source/raster/backing.d` | Retained backing and lease lifetime are described; several trusted boundaries require proof review. An internal Ddoc paragraph referenced a historical phase code. | Verify retained control-block copying, release transitions, GC scan range, and each trusted operation. |
| `source/raster/validation.d` | Layout validation separates resources, descriptors, strides, and typed samples. Trusted boundaries are present. | Verify address reachability and overflow handling against the documented proof obligations. |
| `source/raster/region.d` | Coordinate-space neutrality, empty regions, and overflow-safe extent handling are documented. | Review method-level failure and `.init` states. |
| `source/raster/descriptor.d` | Sample-element signed strides and descriptor coordinate origin are documented. | Check consumers for consistent units and alignment assumptions. |
| `source/raster/convolution.d` | Fixed convolution delegates spatial traversal to neighbourhood execution. | Verify coefficient order, accumulator behavior, and examples. |
| `source/raster/neighbourhood.d` | Describes resident-source neighbourhood semantics. Public module documentation still named the M2.3 development phase. | Verify overlap, no-write, resident-halo, and row-major contracts. |

The historical phase references were removed from `backing.d` and
`neighbourhood.d` without changing their technical meaning.

  algorithms, ownership rules, and numerical branches exist.

  cannot substitute for executable negative/positive safety tests.

  symbol visibility, and all required rendered Examples.

  frozen source contract.

  their outcomes in issue #198.

items complete until those checks have been performed and verified.
