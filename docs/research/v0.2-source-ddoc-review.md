# v0.2 source-comment and Ddoc review

**Status:** In progress; partial source inventory, not a completed release gate.  
**Branch baseline:** `release/0.2` at `1465ee41ebc23d7f5538d5e2d0a8b313a64f7411`  
**Frozen public API:** `freeze/api-0.2.0` at `1ea67cb6ffb2c887f78d160249a293ad74ba5cda`

## Scope and standard

The release documentation standard is `docs/ddoc-style.md`.
The source Ddoc attached to declarations is authoritative; generated DDox is a
derived publication artifact. Review must distinguish the supported root
import (`import raster;`) from package-private constructors and execution code.

A complete review requires reading **every** supported public declaration and
nontrivial internal function, checking the actual rendered public-only DDox site,
and recording human judgments on semantics and explanations. CI success alone
does not establish that standard.

## Third pass: remaining root-exported API modules

The sixteen remaining root-exported modules were fetched and screened for
module-level Ddoc, release-phase references, and the broad subject of their
public contract:

- Sample/layout: `sample.d`, `byte_layout.d`.
- Pointwise and arithmetic: `fill.d`, `transform.d`,
  `transform_into.d`, `zip_transform_into.d`, `arithmetic_into.d`,
  `transform_allocated.d`.
- Reduction: `reduction.d`.
- Neighbourhood policy/execution: `neighbourhood_shape.d`,
  `border_policy.d`, `neighbourhood_into.d`.
- Copy/conversion: `copy.d`, `conversion_policy.d`,
  `conversion.d`, `conversion_allocated.d`.

Three source comments still named internal milestone identifiers even though
the documented behavior is part of the current API. These were revised:

- `transform.d`: describe semantic pointwise transformation without
  referring to M2.2.
- `reduction.d`: state the documented NaN extrema outcome without
  referring to M3.1.
- `conversion_allocated.d`: state that exact conversion is the sole
  supported v0.2 policy without referring to M3.5.

The `border_policy.d` module overview also implied that type-level policy
selection drives current spatial kernels. It now explicitly states that the
v0.2 neighbourhood and convolution operations require resident source context
and do not accept border policy arguments. This matches the frozen API audit.

This completes an **initial module-level scan** of the root-exported modules;
it does not complete function-level Ddoc, trusted-proof, or generated-site
review.

## Ownership and trusted-boundary review: targeted pass

Reviewed the source bodies and Ddoc around retained ownership and sample access
at the `release/0.2` base commit `580cd06ca0fc489e746deae45c2cebeecfbbad57`.

| Boundary | Source observation | Remaining evidence |
| --- | --- | --- |
| `RasterBackingOwner.retain/release` | Reference count is non-atomic, checked against overflow, and decremented on release; the last owner removes the GC scan range, destroys backing, then frees the control block. | Recheck copying/assignment/reentrancy and thread-sharing assumptions against external compiler probes and runtime tests. |
| `RasterLease.view/tryWritableView` | Default/inert lease returns inert views; writable borrow requires mutable lease and completed validation/certification; borrow is lifetime-bound to the lease. | Confirm DIP1000 and ordinary-mode negative escape probes cover all return and receiver forms. |
| `RasterView.trySample` | Returns a value copy, checks band/region bounds, and relies on constructor validation for signed-stride address arithmetic and reachability. | Review each trusted read/ROI/execution adapter and signed-stride regression matrix. |
| `WritableRasterView.trySetSample` | Uses a narrow trusted `const(void)*` to `T*` conversion after writable certification; checks band and coordinates before writing. | Validate that all factories certify access and no uncertified path constructs a writable view. |
| `validation.checkedCoordinateStride` | Guards positive and negative stride multiplication, including the `ptrdiff_t.min` magnitude. | Check extreme-value tests for both coordinate axes and summed offsets. |
| `validation.validResourceRange` | Rejects non-null-length/null-base metadata and integer address-range wraparound. | Check all callers validate resources before forming `resourceEnd`; integer range checks alone do not prove actual mapped storage. |

This targeted review produced three explanatory Ddoc changes:
- `RasterLease` now explicitly documents non-atomic retained ownership and the
  fact that writable borrows are neither exclusive nor independently retained.
- `RasterView.trySample` no longer speaks about a future adapter; it describes
  the present package-internal execution distinction.
- `validResourceRange` explicitly distinguishes address-range
  representability from ownership or mapping.

**Important:** This is not a proof of memory safety or a complete
function-by-function audit of all `@trusted` boundaries. No source semantics,
attributes, signatures, or tests were changed.
